# Бот «Женщины нового времени»

Telegram-бот сценарной воронки: приветствие → опрос с множественным выбором →
презентация сообщества → правила → вступление (бесплатное на первые 1000 мест,
затем платное через ЮKassa). Финальное сообщение временно без ссылок на
канал/чат — это осознанный пропуск, он описан ниже.

## Что уже готово

- Полный сценарий Пост 1 → Пост 2 → Правила → финал, с множественным выбором
  и свободным текстом «Свой вариант».
- Каждый шаг пишется в PostgreSQL (таблицы `users`, `funnel_answers`, `events`,
  схема — в `sql/schema.sql`). База своя, на сервере в Selectel, бот
  подключается к ней через `DATABASE_URL` (asyncpg).
- Уведомления команде при ответе на опрос и при вступлении — `ADMIN_CHAT_ID`
  может содержать один или несколько адресатов через запятую (личные чаты
  и/или группы), если пусто — бот просто не шлёт их, всё остальное работает.
- Оплата 990₽ после первых 1000 бесплатных мест: `bot/handlers/funnel.py`
  (`accept_rules`) считает занятые места (`db.count_occupied_spots`, статусы
  `joined`/`paid`) и после лимита шлёт `bot.send_invoice(...)` через провайдера
  ЮKassa. Пока в `.env` не задан `PAYMENT_PROVIDER_TOKEN` — бот пропускает и
  вступивших после лимита бесплатно, но помечает это событием
  `join_without_payment` в базе и уведомлением в админ-чат, чтобы это было
  заметно. Как только получите токен провайдера (BotFather → Payments →
  подключить ЮKassa) — впишите его в `.env`, и оплата включится сама, без
  правок кода.
- Прокси до `api.telegram.org` (актуально для сервера в РФ, если Telegram
  напрямую недоступен): задаётся строкой `PROXY_URL` в `.env`, вида
  `socks5://login:password@host:port` (или `http://...` для HTTP-прокси).
  Пусто — бот ходит в Telegram напрямую, без прокси.
- Автоперезапуск при падении — systemd (`Restart=on-failure`, без предела
  попыток, с растущей паузой между ними) сам поднимает бота, если он упал,
  и продолжает пробовать сколько угодно (не сдаётся навсегда), файлы в
  `deploy/` (подробности ниже, в разделе «Запуск на сервере»). Уведомление о
  падении в `ADMIN_CHAT_ID` шлёт `deploy/notify_down.sh` — но оно бессильно
  ровно в одном случае: если упал именно прокси до Telegram, самому боту
  нечем пожаловаться (тот же сломанный канал). Для этого случая — отдельный
  «сторож» ниже.
- **Сторож (watchdog) на GitHub Actions** — бесплатно, без сторонних
  сервисов: `.github/workflows/watchdog.yml` каждые 5 минут стучится на
  `http://<сервер>:8080/health` (эндпоинт бота, `bot/health.py` — раз в
  минуту проверяет связь с Telegram, отдаёт 200/503). Если бот перестал
  отвечать — присылает в Telegram (через `WATCHDOG_BOT_TOKEN`/
  `WATCHDOG_ADMIN_CHAT_ID`, секреты репозитория на GitHub, не `.env`)
  сообщение «⚠️ не отвечает», а когда отойдёт — «✅ снова работает».
  Работает даже когда сломан именно прокси бота, потому что запускается на
  серверах GitHub, а не на нашем сервере в России. Состояние (чтобы не
  спамить каждые 5 минут) хранится в закоммиченном файле
  `.github/watchdog-state.txt`.

- **Модерация сообщений в темах групп сообщества** (поддерживает сразу
  несколько разных групп): если заполнить `MODERATION_CHAT_ID` и
  `MODERATED_TOPICS` в `.env`, бот начнёт автоматически удалять сообщения в
  указанных темах (например, «Вакансии»), слать их на проверку в отдельный
  служебный чат с кнопками «Опубликовать»/«Отклонить», и при одобрении
  публиковать их обратно в ту же тему с подписью автора. Код — в
  `bot/handlers/moderation.py`, очередь заявок — в таблице
  `moderation_queue`. Пока переменные пустые — эта часть бота полностью
  выключена, остальной сценарий не затрагивает.

- **Анкета на отбор перед вступлением.** Последний шаг воронки: вместо
  `FINAL_MESSAGE` бот присылает `SCREENING_INTRO_TEXT` (3 вопроса «на
  адекватность»), человек отвечает одним сообщением, ответ вместе с именем,
  фамилией и телефоном (которые сохраняются при шаринге контакта в начале
  воронки) падает в `SCREENING_CHAT_ID` с кнопками «✅ Принять» / «❌
  Отклонить». Принято — пользователю уходит `SCREENING_APPROVED_TEXT` (текст со
  ссылкой на канал `@newerawomenworld`). Отклонено — уходит
  `SCREENING_REJECTED_TEXT` с кнопкой «Заполнить анкету заново» — повторная
  подача разрешена без ограничений. Код — в `bot/handlers/screening.py`,
  заявки — в таблице `screening_applications` (статусы `awaiting_answers` →
  `pending` → `approved`/`rejected`). Состояние анкеты хранится в БД, а не в
  FSM — переживает рестарт бота. Пока `SCREENING_CHAT_ID` пустой — анкета
  выключена, воронка заканчивается прежним `FINAL_MESSAGE`, как раньше.
  ⚠️ Если оплата подключена и человека отклонили уже после оплаты — деньги
  возвращаются вручную, автовозврата нет.

## Что пока не подключено (и где это добавить)

1. **Ссылки на канал и чат сообщества для тех, кто проходит без анкеты.**
   Пока `SCREENING_CHAT_ID` не настроен, воронка заканчивается константой
   `FINAL_MESSAGE` в `bot/texts.py` — она ещё заглушка. Одобренным анкетой
   уже уходит настоящий текст со ссылкой на канал (`SCREENING_APPROVED_TEXT`).
2. **Реальные ссылки на политику конфиденциальности и договор оферты.** Сейчас
   в `bot/texts.py` — заглушки `PRIVACY_POLICY_URL` / `OFFER_AGREEMENT_URL`.
3. **`SCREENING_CHAT_ID` для анкеты на отбор.** Инвайт-ссылка на служебный
   чат уже есть у команды, но бот присоединяется к чату не по ссылке — его
   нужно добавить туда как участника/админа вручную через интерфейс
   Telegram, а затем получить числовой `chat_id` этого чата (например, по
   любому сообщению в логах бота, `logging.basicConfig(level=logging.INFO)`
   уже включён) и вписать в `.env`.

## Запуск на сервере (Selectel)

База — обычный PostgreSQL, поднятый на самом сервере, поэтому бот и запускается
прямо там же (с Мака к базе напрямую не достучаться, `DATABASE_URL` в `.env`
использует `localhost`).

1. Создать бота через [@BotFather](https://t.me/BotFather), получить токен.
2. На сервере поднять PostgreSQL и выполнить `sql/schema.sql` (например,
   `psql "$DATABASE_URL" -f sql/schema.sql`).
3. Заполнить `.env` (пример — в `.env.example`):
   ```
   BOT_TOKEN=токен от BotFather
   DATABASE_URL=postgresql://user:password@localhost:5432/dbname
   ADMIN_CHAT_ID=       # один chat_id или несколько через запятую, можно оставить пустым
   PAYMENT_PROVIDER_TOKEN=  # можно оставить пустым пока не подключена ЮKassa
   PROXY_URL=           # можно оставить пустым, если Telegram доступен напрямую
   MODERATION_CHAT_ID=  # можно оставить пустым, пока не нужна модерация тем
   MODERATED_TOPICS=    # пары chat_id:thread_id через запятую, например -1001111:12,-1002222:34
   SCREENING_CHAT_ID=   # можно оставить пустым, пока не нужна анкета на отбор
   ```
4. Установить зависимости и запустить:
   ```
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   python -m bot.main
   ```
5. Для постоянной работы и автоперезапуска — поставить systemd-сервис:
   ```
   bash deploy/install.sh
   ```
   Это создаст сервис `wnw-bot`, включит его автозапуск при перезагрузке
   сервера и настроит `Restart=on-failure` — при падении бот сам
   перезапускается. Если упасть подряд 5 раз за минуту (например, сломалась
   БД или сервер перезагрузился) — systemd остановит попытки и пришлёт
   уведомление о падении в `ADMIN_CHAT_ID` (через `deploy/notify_down.sh`).
   При обычном `systemctl restart` (например, после деплоя новой версии)
   уведомление не шлётся — оно только про настоящее падение.
   Проверить статус: `sudo systemctl status wnw-bot`, логи —
   `sudo journalctl -u wnw-bot -f`.
   `Procfile` в проекте оставлен на случай переезда на Railway/аналоги, для
   Selectel он не нужен.
